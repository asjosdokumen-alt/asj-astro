Verdict

Lapisan backend ini fungsional kaya, tetapi postur keamanannya lemah: tiga temuan KRITIS (cache key tanpa identitas sesi pada endpoint data privat, penghapusan file storage lintas-kandidat via folder bebas, dan kebocoran sessionToken admin melalui payload job) semuanya dapat dieksploitasi tanpa kredensial khusus dan berasal dari satu akar masalah yang sama — guard sesi divalidasi di handler tetapi tidak dipertahankan pada jalur caching/async/polling. Pola IDOR berulang (cekDataPelamar, prefill tanpa sesi, submitApply overwrite) menunjukkan helper isOwnerOrAdmin ada tetapi tidak dipakai konsisten. Prioritas perbaikan: kunci cache dan payload job dulu (dampaknya paling luas), lalu satukan pengecekan kepemilikan di satu guard yang dipanggil semua handler dokumen, dan terakhir selaraskan wrapper lama (netlify-wrapper.ts) dengan hardening surface. Setelah itu, konsolidasi entry lama vs surfaces akan menyelesaikan sisa temuan duplikasi dan jalur mati secara alami.
