## 1. Yang benar-benar berubah

### 1.1 Ultimate Loop — "S bukan akhir, S adalah gerbang"

Masalah yang dijawab: dua siswa yang sama-sama sempurna (100% benar + cepat)
bisa mendapat skor identik, sehingga papan peringkat hanya mengurutkan siapa
yang lebih dulu menekan tombol.

| Berkas | Perubahan |
|---|---|
| `src/lib/arcade.ts` | Blok `ULTIMATE` + `aturanUltimate()` + `bonusUltimate()` + `bolehUltimate()` + `digitPresisi()` + `kunciPresisi()` + `formatSkorPresisi()` + `tandaSiswa()` |
| `src/lib/arcade.test.ts` | 6 tes baru (gerbang S, kurva berplafon, bayaran tak berplafon, presisi milidetik, kunci urut, hash deterministik) |
| `netlify/functions/_lib/game/leaderboard.ts` | `bandingPapan()` mengurutkan **skor → presisi → kedalaman loop → waktu kirim → nomor WA**; `rapikanDetail()` membatasi `presisi` 0..9999 dan `loop` 0..99.999; `batasSkor()` menaikkan plafon ke 10 juta **hanya** bila `detail.loop ≥ 1`; respons membawa `skorTampil`, `presisi`, `loop` |
| `netlify/functions/_lib/game/leaderboard.test.ts` | 6 tes baru (plafon bersyarat, skor sama beda 1 ms, presisi vs skor, loop, tiebreak WA, clamp) |
| `src/lib/skorGame.ts` | `BarisPapanGame` menerima `skorTampil`/`presisi`/`loop` + helper `teksSkorPapan()` |
| `ArcadeGame.tsx` / `KotobaGame.tsx` | Papan menampilkan `skorTampil` (fallback ke angka lama) |
| `ArcadeGame.tsx` | Genba DOM mengirim `presisi` (jumlah milidetik sisa waktu) + `loop: 0` + `ultimate: false` |

Angka yang dipakai:

- Digit presisi = `total sisa waktu (ms) mod 10.000` → 4 desimal, mis. `6.600,3712`.
- Kunci urut = `skor × 10.000 + presisi`. Skor selalu menang; presisi hanya
  memecah skor kembar.
- Pemecah seri terakhir = waktu kirim, lalu nomor WA (unik per siswa), jadi
  **tidak ada dua baris yang bisa berakhir seri**.
- Plafon 10 juta hanya berlaku bila `loop ≥ 1`; skor biasa tetap 1 juta.

Catatan jujur: skor masih dihitung di klien (seperti sebelumnya). `detail`
sekarang dibatasi di server, tetapi server belum menghitung ulang skor. Itu
pekerjaan terpisah dan tidak diklaim selesai di sini.

### 1.3d Paket offline (preflight Wi-Fi)

Tombol **"Unduh paket game (offline)"** ada di kartu CTA `/arcade`. Ia mengunduh
`index.js`, `index.pck`, dan `index.wasm` ke Cache Storage bucket
`asj-godot-v1` **sebelum** bermain, dengan status per berkas. Bucket itu sama
dengan yang dipakai service worker, jadi `ASJGodot.mulai()` berikutnya
dilayani dari cache.

Diuji 2026-11-15: unduh → cache berisi tepat 3 URL → `context.setOffline(true)`
→ reload → HTML lama tetap tampil → tekan Genba → engine `siap`. Artinya
**benar-benar offline**, bukan hanya "file ada di cache".

Catatan lokal: `BaseLayout.astro` sengaja **melepas** service worker di
`localhost`/`127.0.0.1` supaya `astro dev` tidak menyajikan bundel kemarin.
Untuk menguji PWA/offline di server lokal, buka dengan `?pwa=1`; tanpa itu
service worker tidak aktif dan paket offline tidak bisa dipakai.

### 1.3g Offline: dua jebakan yang sekarang dijelaskan

1. **`navigator.onLine === false`** → `fetchLatestVersion` berhenti SEBELUM
   `fetch`, jadi tidak ada `console.error` `/version.json` saat offline.
   Diuji di `appVersion.test.ts` (16 tes).
2. **`unduh()` memeriksa `navigator.serviceWorker.controller`.** Cache Storage
   saja tidak cukup: engine hanya dilayani dari cache kalau SW mengontrol
   halaman. Kalau belum, status berbunyi **"Paket tersimpan. Muat ulang halaman
   sekali agar offline aktif."** — bukan menjanjikan offline yang belum aktif.
   Di localhost, SW memang dilepas kecuali `?pwa=1`.

## 3. Yang belum selesai (jujur)

1. **Skor belum dihitung ulang di server.** Papan sudah kebal seri, tetapi
   klien yang dimodifikasi masih bisa mengirim angka. Kalau skor mau dipercaya,
   server harus menghitung ulang dari event ronde.
   → **2026-11-16: selesai untuk Genba** (`SKOR-SERVER-2026-11-16.md`). Combo,
   Kotoba, dan Matematika masih jalur lama dan ditandai `diverifikasi: false`.
2. **Preflight otomatis belum.** Tombol unduh manual sudah ada dan terbukti
   offline; deteksi "sedang di Wi-Fi, unduh sekarang" belum.
3. **Panggung Combo di Godot masih berperan sebagai pratinjau** sampai event
   kartu asli masuk; setelah itu ia mengikuti permainan DOM. Yang belum:
   memindahkan penilaian kalimat ke Godot — dan itu tidak perlu selama teks
   Jepang tetap DOM.
4. **`public/godot/index.wasm` 38 MB** ikut repo. Untuk repo publik ini besar;
   langkah berikutnya adalah Netlify Blobs/CDN atau build step yang mengunduh
   artefak, bukan menyimpannya di git.
5. **Font CJK di canvas** sengaja tidak dipakai. Teks Jepang tetap DOM; kalau
   nanti ada kebutuhan teks di dalam canvas, subset Noto Sans JP harus
   ditambahkan sebagai keputusan sadar.
